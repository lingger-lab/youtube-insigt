# 계획 — 데이터 근거 시안(제목·썸네일·훅) 생성

작성 2026-09-08. 상태: **1·2·3 구현 완료(2026-09-09)** — 초보자 단순화는 구조 확정 후(ISSUES B9).
구현 요약: `utils/playbook.ts`(원칙 ID·신뢰도·출처), `analysisPrompt.ts`에 채널 평소 제목 대조 표 +
플레이북 + 원본 5부 구조 시안 절(`[행]/[원칙]/[가정]` 강제), `RecentUpload.title`(할당량 0),
`selectCohort` format-median 우선, "내 주제" 입력(보관함 저장), 구독자 대비 카드·정렬 노출.

목적: 원래 앱의 출력물(제목·썸네일·대본 시안)을 되살리되, 이번 세션에서 만든 데이터 위에서 근거를
달고, YouTube가 제공하는 실제 검증 수단(Test & Compare)에 바로 넣을 수 있는 형태로 낸다.
구현은 §2-2의 초안(3안)이 아니라 원본 5부 구조(트리거 → 세트 5개 → 구조 → 매핑표 → 요약)로 했다
— 초기 기획 대조에서 빠진 절을 되살린 결과. §2-2는 당시 초안 기록으로 남긴다.

## 0. 조사 결과

### 0-1. 우리 데이터에 실제로 있는 신호 (실측: "에어프라이어 레시피" 45편, 상위 10 / 하위 10)

| 신호 | 상위군 | 하위군 | 판단 |
|---|---|---|---|
| 제목 길이(자) | 44.5 | 43.1 | **차이 없음** |
| 숫자 포함 | 20% | 20% | 차이 없음 |
| 이모지 | 30% | 10% | n=10에서는 노이즈 |
| 태그 수 | 5.7 | 11.9 | 방향은 있으나 n 작음 |
| 설명 길이 | 245 | 303 | 상위 1위는 설명 **빈 문자열** — Shorts는 설명이 없는 경우가 흔함 |
| 자막 트랙 | 20% | 0% | 의미 미검증(B8) |
| maxres 썸네일 | 100% | 100% | 이미지 분석 가능 |

결론: **텍스트 표면 특징(길이·숫자·기호)만으로는 상위/하위가 갈리지 않는다.** 표 20건에서
LLM이 "제목 패턴"을 세어 말하게 하는 지금 방식은 정직하지만 얇다. 근거가 될 만한 층은 세 가지다.

1. **썸네일 이미지** — 20장 전부 maxres. 지금은 시트로 붙여넣거나 앱 내 경로에서 자동 첨부.
   텍스트 데이터보다 정보량이 압도적으로 크고, 외부 근거(얼굴·감정·글자 수·대비)도 여기 집중.
2. **채널 내부 대조** — 상위군 영상은 "그 채널의 평소"보다 수백 배다. 그 채널의 최근 50편
   제목과 이 영상 제목의 **차이**가 가장 통제된 신호(주제·채널·구독자 동일). 현재
   `recentUploads`는 `id/viewCount/duration/publishedAt/liveStatus`만 저장하는데, 이미 부르는
   `videos.list?part=snippet`에 제목이 **오고 있다** → 저장만 하면 **추가 할당량 0**.
3. **검색어 집합의 주제 분포** — 상위군은 "계란·삼겹살·치킨"처럼 **한 재료 한 결과**, 하위군은
   "10가지 레시피", "축복인 이유", "200% 활용" 같은 모음·에세이형이 많다(실측 표에서 육안).
   이건 제목 길이가 아니라 **약속의 구체성**이며, LLM이 세도록 요청 항목을 바꿔야 잡힌다.

부수 발견: 하위군 10건 중 3건이 구독 305만 채널의 롱폼으로 기준선이 `lifetime-mean`(Shorts
섞인 채널 평균)이라 0.08~0.18배가 나왔다. **신뢰도 낮은 기준선을 대조군에 넣으면 시안 근거가
오염된다** → 대조군 선정에서 `lifetime-mean`을 뒤로 미루거나 제외.

### 0-2. 외부 근거 (신뢰도 표기)

| 근거 | 내용 | 신뢰도 |
|---|---|---|
| YouTube **Test & Compare** | 썸네일 3종 A/B(2024) → **2025-12 제목·제목+썸네일 조합도 3종까지**, Advanced Features 켠 모든 채널. 승자는 CTR이 아니라 **노출당 시청시간**. 변형당 1,000~5,000 노출, 최대 2주. 공개 롱폼·팟캐스트·라이브 아카이브만(Shorts 불가) | 높음 (YouTube 공식 기능, 복수 매체) |
| 제목 길이 | 18,080채널 11니치 연구: **30~50자 최적**, 90자+ 일관된 불이익. 단 Gaming·Entertainment·**Food**는 30자 미만이 이김. 숫자는 Tech·Business·Fitness·Food에서만 유효 | 중간 (업체 자체 연구, 영어권) |
| 썸네일 | 글자 3~4단어 이하, 얼굴+감정, 피사체-배경 대비, 제목과 **중복하지 않고 보완**. "얼굴 2.3배 CTR" 류 수치는 출처가 마케팅 블로그 | 낮음~중간 (수치는 검증 불가, 방향은 일관) |
| Shorts 훅 | 이탈의 50~60%가 첫 3초. 70% 이상 "본 vs 넘김"이 목표. 첫 프레임을 가장 강한 장면으로 | 중간 (여러 분석 도구 데이터, 자체 조사) |
| 알고리즘 | 클릭보다 시청시간. 오해 유발 썸네일은 CTR↑ 후 추천↓ | 높음 (YouTube 공식 서술과 일치) |
| LLM 학술 | 오해 썸네일 **탐지**는 LLM이 잘함(Claude 3.5 Sonnet 93.8%). 상위 영상에 근거한 **생성**의 품질 평가 논문은 없음 | 높음(탐지) / 없음(생성) |

의미: 시안의 좋고 나쁨을 **앱이 판정할 방법은 없다**. 있는 것은 (a) 관찰에 근거를 달게 하는
것, (b) 오해 유발 여부를 LLM에 자기점검시키는 것, (c) **YouTube Test & Compare에 3종을 올려
사용자가 실측**하는 것뿐이다. 그래서 출력 형식을 처음부터 "3종 세트"로 맞춘다.

## 1. 목표

사용자가 "내 주제"를 입력하면, 검색 결과의 상위/하위 대조 + 썸네일 + 채널 내부 대조에서
관찰된 패턴을 **행 번호로 인용**하며 **제목 3안 + 썸네일 지시 3안 + 첫 3초 훅 3안**을 낸다.
3안은 서로 다른 가설(예: 구체 약속형 / 금지형 / 결과 노출형)을 대표해 Test & Compare에 그대로 올린다.

원래 프롬프트의 3부 구조(트리거 분석 → 썸네일/제목 세트 → 대본 구조)를 유지한다.

## 2. 범위

### 2-1. 데이터 (할당량 0 증가)
- `RecentUpload`에 `title` 추가 (`search.ts`의 `videos.list` 응답에서 이미 옴). 스키마·타입·테스트.
  이력 저장 크기 +약 30% (제목 50자 × 50편 × 36채널) — 예산 3.5M자 안.
- `selectCohort`: 기준선 `format-median`을 우선, `lifetime-mean`은 자리가 남을 때만. 테스트.
- 채널 내부 대조 표: 상위군 각 영상에 대해 "같은 채널 최근 업로드 중 중앙값 근처 3편의 제목"을
  붙인다 (프롬프트 길이 +약 1,500자).

### 2-2. 프롬프트 (`analysisPrompt.ts`)
`buildMarketAnalysisPrompt` / `buildSingleVideoPrompt`에 **시안 절**을 추가. 새 함수가 아니라
기존 프롬프트 뒤에 `proposalSection(topic)`을 붙인다 (관찰 → 시안 순서가 근거 인용의 전제).

```
# 내 주제
{사용자 입력. 없으면 "검색어와 같은 주제로 가정" 표기}

## 관찰 (기존)  … 상위/하위 표, 채널 내부 대조 표, 없는 데이터, 요청 1~6

## 시안 — 위 관찰에 근거해서만
7. 클릭 트리거: 상위군에서 반복되는 "약속의 형태"를 3개 이하로 명명하고 각각 상위 n건/하위 n건.
8. 제목 3안: 각 안은 서로 다른 트리거를 대표. 형식 [안 | 제목 | 근거 행 번호 | 길이(자)].
   30~50자(Food 등은 더 짧게), 90자 금지. 상위군 제목을 베끼지 말고 형태만.
9. 썸네일 지시 3안: 글자 ≤4단어, 제목과 중복 금지, 피사체·표정·대비를 지정.
   시트가 첨부됐을 때만 상위군 썸네일 #번호를 근거로; 없으면 "이미지 미첨부 — 일반 원칙만"으로 표기.
10. 첫 3초 훅 3안: 첫 프레임 + 첫 문장. 자막이 있으면 상위 영상 첫 문장을 인용, 없으면 [가정] 표기.
11. 자기점검: 각 안이 오해를 유발하는가(썸네일·제목이 본편에서 지켜질 약속인가) Y/N + 이유.
12. 검증 방법: 3안을 YouTube Studio Test & Compare에 올려 2주 후 승자 채택 (롱폼만 가능,
    Shorts는 수동 비교) — 앱이 판정하지 않는다는 사실을 프롬프트에 적는다.

규칙: 근거 없는 안은 [가정] 표기. "내부 사고 숨김"·"부족하면 가정하고 진행" 금지 (회귀 테스트).
```

### 2-3. UI
- "내 주제/채널" 입력란 (시장 분석 카드 위). 보관함에 `topic` 저장, 검색 이력에도 같이.
- 버튼은 기존 유지("시장 분석 복사"에 시안 절이 포함). 별도 버튼을 늘리지 않는다.
- 앱 내 LLM 경로도 동일 프롬프트라 자동 적용.

### 2-4. 테스트
- `history`/`schema`: `title` 필드 왕복.
- `selectCohort`: lifetime-mean 후순위.
- `analysisPrompt`: 시안 절 존재, 근거 행 번호 요구, 3안·길이 규칙, 금지 문구 부재, 주제 미입력 시
  "가정" 표기, 시트 미첨부 시 썸네일 근거 제한 문구.
- 시나리오 스크립트로 실제 데이터 프롬프트 생성 → 길이·구조 확인 (할당량 0, 캐시 사용).

## 3. 검증 (완료 조건)
- tsc 0 · lint 0 · 테스트 전건 · build 0 · 번들 AIza 0
- 실제 데이터로 만든 프롬프트를 **외부 LLM에 붙여넣어** 시안이 행 번호를 인용하는지, [가정]
  표기가 나오는지 1회 육안 확인 (사용자 계정, 비용 사용자 부담 — 앱 내 키 없음)
- 문서: CLAUDE.md 제품 제약 절에 "시안의 품질은 앱이 판정하지 않는다 — Test & Compare가 검증"

## 4. 하지 않는 것
- 썸네일 **이미지 생성**(FLUX 등): 별도 비용·의존성. 지시문까지만.
- CTR 예측 점수: 근거 없는 숫자를 만들지 않는다.
- 대본 전문 작성: 자막 없이 대본을 쓰면 창작. 훅(첫 3초)과 구조까지만.
- 댓글 수집(D절), 시간창 표본(보류) — 별건.

## 5. 위험
- 시안이 그럴듯한 창작으로 되돌아갈 위험 → 근거 행 번호·[가정] 강제 + 자기점검 항목. 그래도
  **LLM 답변 품질은 앱이 보장 못 함**. 사용자 검증(Test & Compare)이 유일한 판정.
- 대조군 n=10은 통계가 아니다. 프롬프트가 "경향"이라고만 말하게 한다.
- 채널 내부 대조 표로 프롬프트가 7~8천 자 → 외부 LLM 붙여넣기엔 문제없음, 앱 내 경로 토큰 +30%.
